# SPEC: Marketplace Discovery UI (GitHub Pages)

## 1. Purpose and target users

**Purpose.** Build a static site on GitHub Pages that lets users of the marketplace (`dev-digest-ai-marketplace`) find the plugin/skill/command/agent they need through keyword search and catalog browsing — with no real backend at all. All search and all logic run on data generated during a CI build step.

**Target users:**
- Developers looking for a ready-made skill/agent/command for a specific task ("I need a skill for X").
- New team members who need to understand how to add the marketplace in 30 seconds.
- Contributors who want to see the catalog's "health" (how many plugins, what's new) and copy install commands.
- Other agents/LLM tools that need a machine-readable catalog listing (`llms.txt`, `index.json`).

**Out of scope for this spec:** the plugins/skills themselves (`plugins/**` content), user authentication, any server-side backend or database.

## 2. Technology stack (approved)

| Decision | Choice |
|---|---|
| Frontend | Vanilla HTML/CSS/JS, ES modules, no bundler or framework |
| Index generation + deploy | GitHub Actions → publish to `gh-pages` via `actions/deploy-pages` |
| Search library | Fuse.js (vendored into the repo at build time, no runtime CDN) |

`fuse.js` is pinned to exact version `7.0.0` in `package.json` (no `^` range): `7.1.0`+ dropped the UMD global build (`dist/fuse.min.js`) that `site/index.html` loads as a classic `<script>` for `window.Fuse`. Bumping past `7.0.0` means switching `index.html`/`app.js` to the ESM build (`fuse.min.mjs` + `import`) as a deliberate, separate change — not a silent dependency bump.

## 4. Commands

| Command | What it does |
|---|---|
| `npm run build:index` | Runs `scripts/build-index.mjs`: generates `site/data/*.json`, `site/llms.txt`, `site/index.json`, `site/feed.xml`, copies `fuse.min.js` into `site/js/vendor/` |
| `npm run serve` | `scripts/serve-site.mjs` — zero-dependency static server to preview `site/` at `localhost:4173` |
| `npm test` | `scripts/run-tests.mjs` — finds `test/**/*.test.mjs` and runs them via `node:test`'s `run()` API (plain `node --test <dir>` doesn't recurse into a directory argument on Node 22.20, and shell globstar isn't portable across sh/bash/CI) |
| `npm run validate` | `validate-marketplace.mjs` (structural lint) + `validate-plugins.mjs` (`claude plugin validate` per plugin) |

`npm run lint` is not implemented yet (no ESLint/Prettier config) — out of scope for the first iteration, add if real stylistic drift shows up in review.

## 5. Code style

- Plain ES modules (`<script type="module">`), no transpilation and no bundler.
- One file, one responsibility (`search.js` doesn't know about `favorites.js`; they communicate through invocation from `app.js`, with no shared global state).
- `scripts/*.mjs` are pure functions with deterministic output (stable sort order, stable JSON key order) so that git diffs of generated files (on `gh-pages`) stay readable.
- CSS: custom properties for theming (`prefers-color-scheme` light/dark), no CSS frameworks.
- ESLint/Prettier: minimal config, only baseline rules, no stylistic bikeshedding.
- No "what the code does" comments — only where the reason is non-obvious (e.g. why the permalink is built from a commit SHA instead of `main`).

## 6. Testing strategy

- **Indexer (`scripts/**`):** unit tests with `node --test` — correct parsing of `plugin.json`/frontmatter, handling of missing fields, tag deduplication, correctness of `stats.json`, correctness of the `changelog.json` diff, validity of the generated XML/JSON.
- **UI modules:** jsdom + `node --test` — Fuse.js returns the expected cards for a fixed sample index; filters narrow the result; URL state (`?q=...&type=...`) is read/written correctly; favorites survive a reload (mocked `localStorage`).
- **CI gate:** `validate.yml` runs structural lint + `claude plugin validate` + `build:index` + `test` as a required check on every PR and on push to `main` — the merge is blocked on failure.
- **Before deploy:** `build:index` + `test` run again in `deploy.yml` before publishing to `gh-pages`, so a build that would break the live site never gets that far.
- Full E2E (Playwright) is out of scope for the first iteration; added as a separate decision if needed (see "Ask first" below).

## 7. Boundaries

**Always:**
- `npm run validate` and `npm test` must pass before every merge to `main` and every deploy.
- Generated files (`site/data/*.json`, `site/js/vendor/*`, `site/llms.txt`, `site/index.json`, `site/feed.xml`) are only ever changed by `scripts/build-index.mjs` — never edited by hand.
- `scripts/build-index.mjs` treats `plugins/**` content (including markdown/JSON) as data, not code — no `eval`/`exec` over plugin content.
- Deploy to `gh-pages` happens only through `actions/deploy-pages` with the default `GITHUB_TOKEN`, no custom PATs or secrets.

**Ask first before:**
- Adding any runtime call to an external API from the browser (e.g. live GitHub stars via the REST API) — by default all data comes only from the build-time index.
- Adding a new runtime dependency loaded from a CDN (by default everything is vendored into the repo).
- Changing the repository's GitHub Pages settings (source/branch).
- Enabling analytics or any user tracking.

**Never:**
- Store user PII or credentials (favorites are anonymous `localStorage` only, no accounts).
- Commit secrets/tokens to the repository.
- Publish a build to `gh-pages` that hasn't passed `validate`/`test`.

## 8. Modules (in build order)

### 8.1 `indexer` — build-time data pipeline
**Dependencies:** none.
**Input:** `plugins/**`, `.claude-plugin/marketplace.json`, git history (for the changelog).
**Output:** `site/data/search-index.json`, `site/data/stats.json`, `site/data/changelog.json`.

`search-index.json` entry schema:
```json
{
  "id": "plugin-name/skills/skill-name",
  "type": "plugin | skill | command | agent",
  "pluginName": "plugin-name",
  "name": "Name",
  "description": "Short description",
  "tags": ["review", "quality"],
  "path": "plugins/plugin-name/skills/skill-name/SKILL.md",
  "githubUrl": "https://github.com/<owner>/<repo>/blob/<commit-sha>/plugins/.../SKILL.md",
  "version": "1.2.0",
  "validated": true,
  "installCommand": "/plugin install plugin-name@dev-digest-ai-marketplace"
}
```
**Done when:** the script deterministically (same output for the same input) generates all three files, and exits with a non-zero code and a clear message if a `plugin.json` doesn't match the schema.

### 8.2 `deploy-pipeline` — CI/CD
**Dependencies:** none (built in parallel with the indexer).
**Output:** `.github/workflows/validate.yml` (extends the pre-existing structural-lint workflow with `build:index` + `test`), `.github/workflows/deploy.yml`.
**Done when:** a PR with an invalid plugin is blocked by the required check; a push to `main` deploys the updated site to `gh-pages` in under 5 minutes.

### 8.3 `search-ui` — search and browse
**Dependencies:** `indexer`.
**Logic:** loads `data/search-index.json`, builds a Fuse.js index over the `name` (highest weight), `tags`, and `description` fields; filter chips for `type` and `tags`; card rendering via `cards.js`.
**Done when:** a keyword search finds the matching cards by name/tag/description; a type filter narrows the list without a page reload; an empty query shows the whole catalog.

### 8.4 `catalog-extras` — discovery widgets
**Dependencies:** `indexer`, shares the page frame with `search-ui`.
- **Stats tile:** reads `stats.json`, shows counts (plugins/skills/commands/agents) and the last build date.
- **What's new:** reads `changelog.json`, shows the last N entries (date, type: added/updated/removed, link to the card).
- **Onboarding block:** static text + copy buttons for the `marketplace add` / `install` commands.
**Done when:** all three widgets render from the real generated files with no hardcoded numbers in the HTML.

### 8.5 `machine-readable` — outputs for other tools/agents
**Dependencies:** `indexer` (independent of the UI).
**Output:** `site/llms.txt` (a human- and LLM-readable listing), `site/index.json` (a public copy of the catalog — `{ version: 1, marketplace, generatedAt, commit, items }`, a stable contract versioned separately from the internal `search-index.json`), `site/feed.xml` (RSS of recent changes, built from `changelog.json`). These live at the site root, not a separate `public/` folder, because `index.html` links to them with relative paths (`href="llms.txt"`).
**Done when:** all three files are valid (JSON parses OK, XML is well-formed) and reachable at predictable URLs after deploy.

### 8.6 `card-actions` — actions on a card
**Dependencies:** `search-ui`.
- Copy install command (from the `installCommand` field).
- GitHub permalink (from `githubUrl`, pinned to the build's commit SHA, not to `main`).
- "Validated" badge (from the `validated` field, set by the indexer via `claude plugin validate`; if the CLI isn't available on the CI runner, the badge reads "schema-only").
- Compare: pick up to 3 cards via checkbox → a field-difference table.
**Done when:** the copy button puts the exact install string on the clipboard; the permalink opens the exact file at the commit the site was built from.

### 8.7 `personalization` — client-side state
**Dependencies:** `search-ui`.
- Favorites: toggle icon, stored in `localStorage` under the key `marketplace:favorites`.
- Shareable URL: `?q=&type=&tag=` stays in sync with search state via `history.replaceState`.
**Done when:** favorites survive a page reload; a URL with copied parameters reproduces the same search result in a different browser/tab.

## 9. Project-wide acceptance criteria

- The site is fully static — no server-side code or endpoint.
- Search and all filters work offline after the first page load (data is already on the client).
- CI blocks merge/deploy on an invalid plugin or a failing test.
- All 7 modules from §8 are implemented and pass their own "Done when" criteria.
